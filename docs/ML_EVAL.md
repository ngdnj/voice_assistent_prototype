# Качество и экономика LLM-интерпретации (eval)

Для кого: роль 6 (экономика, слайды) и все, кто меняет промпт или модель.
Что измеряется: только интерпретация запроса LLM-агентом — какой инструмент вызван, с какими аргументами и что сказано пользователю.
ASR и выполнение в настоящем хранилище здесь не оцениваются (AGENTS §15: отдельно).

## Набор

Классы запросов из AGENTS §15. Каждый класс разделён на выборки:

- `tune` — по этим кейсам правится промпт; сюда же фразы из живого тестирования;
- `holdout` — только итоговый замер, промпт под них не правится. Если holdout-кейс понадобилось чинить промптом, его переносят в `tune` и пишут новый.

| Класс | Что проверяется | tune | holdout | Всего |
|---|---|---|---|---|
| create | создание задачи, встречи, напоминания: тип, время или дата задачи, название | 21 | 10 | 31 |
| period | вопрос за период: полуинтервал `[start, end)`, типы | 12 | 12 | 24 |
| clarify | нет времени или оно невозможно: уточнить и не создавать; ответ на уточнение | 6 | 16 | 22 |
| search | поиск старой записи по смыслу: запрос, ответ | 6 | 16 | 22 |
| general | общий вопрос, благодарность, отказ: ничего не создавать и не удалять | 5 | 16 | 21 |
| delete | без `delete_event` (MVP): «пока не умею», ничего не вызывать — 1 кейс; с `--enable-delete`: удаление — 5 кейсов | 6 | 0 | 6 |

Опорное время большинства кейсов — понедельник 2026-10-19 12:00, Europe/Moscow.
Часть кейсов идёт в другой зоне (Asia/Yekaterinburg, Asia/Vladivostok), в том числе когда тот же момент UTC — уже другие сутки у пользователя, и перед полуночью (повтор запроса не меняет опору).
Фразы из живого тестирования: несколько дел в одной фразе, оговорки («в 15, нет, в 16»), «вчера в 15:00», «в 25:00», «в следующую пятницу».

Политика «в следующую пятницу» не зафиксирована: принимаются обе пятницы (23 и 30 октября).

Кейсы: `evals/cases.py`. Проверки: `evals/checks.py`.

## Как запускать

```bash
PYTHONIOENCODING=utf-8 uv run python -m evals.run --repeat 3                  # весь набор
PYTHONIOENCODING=utf-8 uv run python -m evals.run --split holdout --repeat 3  # итоговый замер
uv run python -m evals.summary --write docs/ML_EVAL.md                        # обновить таблицу ниже
```

Каждый кейс — новое хранилище и история, одна модель на прогон.
Сбои API и сети считаются отдельно и в точность не входят.

## Результаты

Строка — последний полный прогон модели для каждого хранилища: `postgres` — настоящий MCP-сервер роли 4 на PostgreSQL (`--mcp postgres`, это продуктовый путь), `stub` — SQLite-заглушка. N — число запусков (кейсы × повторы). Все строки сняты 26.10.2026 на одном и том же коде агента; заглушка — до последних правок промпта (правило 14) и примечания про задачи без срока.
Латентность — весь кейс, включая все реплики диалога; это время LLM-агента без ASR и очереди.

Точность двумя числами:

- «строго» — выполнены все ожидания кейса;
- «по поведению» — попытка `create_event`, которую отклонили проверка `arg_checks` или сервер, не считается провалом: записи пользователя не изменились, а финальный ответ проверяется как обычно.

Токены: «вход без кэша» — то, что GigaChat тарифицирует (`prompt_tokens`); «кэш» — префикс промпта из кэша (`precached_prompt_tokens`), [не тарифицируется](https://developers.sber.ru/docs/ru/gigachat/guides/counting-tokens); полный вход — их сумма.

Стоимость показана двумя числами (AGENTS §15):

- «факт» — сколько списано за прогон. На предоплаченном пакете GigaChat это 0;
- «по тарифу» — те же реальные токены по [тарифу GigaChat API для юрлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs): GigaChat-2-Max, синхронно, 0,65 ₽ за 1000 токенов с НДС, одна цена на вход и выход (пакет 30 млн за 19 500 ₽ даёт ту же цену). Кэш не тарифицируется. Проверено 26.10.2026. Это стоимость вычислений без бесплатного лимита; пакет — отдельной строкой под таблицей.

## Ограничения замера

- Текстовый вход: ошибки ASR не учтены.
- Строки `postgres` идут через настоящий сервер роли 4 (HTTP, заголовки, PostgreSQL `it_gorky_test`), но часы сервера в каждом кейсе поставлены на время кейса (кейсы датированы 19.10.2026), а описания инструментов локально дополнены (`app/mcp_server/server.py`, `ROLE 4`). Строки `stub` — SQLite-заглушка.
- Контракт инструментов — AGENTS §8 (T2): `get_events_by_period`, `query`, `date` либо `datetime`, полуинтервалы. До T2 (прототипный контракт, отчёт `20261021-170118`): tune 141/150, holdout 222/225, всего 363/375 (97%). После T2: всего 353/363 (97%). Наборы не совпадают: без флага не идут 5 кейсов удаления (с `--enable-delete` — 15/15), добавлен `delete_unsupported`.
- 5 holdout-кейсов (`h_vlad_thursday`, `h_multi_doctor_and_son`, `h_weekend_plans`, `h_meetings_next_week`, `h_yekb_today_18`) использовались для разбора регрессий T2 и перенесены в tune (`MOVED_TO_TUNE` в `evals/cases.py`). Новые holdout-кейсы вместо них ещё не написаны.
- Разброс между прогонами с одинаковым промптом заметный: например, `past_time_today_asks` дал 3/3 и 0/3 в соседних прогонах ×3.
- Проверка ответа — по ключевым словам; формулировки не оцениваются.
- Латентность зависит от нагрузки на API в момент прогона; параллельно шли другие прогоны.
- Кэш промпта зависит от `X-Session-ID` и от того, как давно был прошлый запрос: в eval запросы идут подряд, поэтому доля кэша (~95% входа) — оптимистичная. При холодном кэше тарифицируется весь вход, ~7 тыс. токенов на кейс, то есть ~4,5 ₽ вместо ~0,2–0,4 ₽.
- Точность holdout получена после того, как промпт правили по tune. Holdout-кейсы для правки промпта не использовались.
