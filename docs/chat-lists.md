# Списки записей в чате

Ответ строится из фактических записей MCP. Модель выбирает период, типы, поиск и
порядок; Python проверяет результат и формирует список. Пример:

```text
Встречи:
1) Завтра, 10:00–11:00 — Обсуждение хакатона
2) Завтра, 15:00 — Созвон с командой
3) 29 октября, 09:30–10:00 — Планёрка
```

Одна запись занимает одну строку. Дата и время идут первыми, длинные вступления
и повторные итоги не нужны. Смешанная выдача озаглавлена «Планы»; в строках дополнительно
указан тип. Время показывается в IANA-зоне пользователя. Если окончание на другой
день, показана и его дата. Год указан, если отличается от года reference_time.
Дата задачи без времени показана с «без времени», задача без срока — «Без срока».
Пустой результат: «Ничего не найдено».

## Порядок

| Просьба | sort | Поведение |
| --- | --- | --- |
| По умолчанию, «ближайшие сначала» | time_asc | Дата/время по возрастанию в выбранном периоде |
| «Сначала дальние», «даты по убыванию» | time_desc | Дата/время по убыванию |
| «Сначала короткие встречи» | duration_asc | Длительность по возрастанию |
| «Сначала длинные», «по длительности» | duration_desc | Длительность по убыванию |
| «По алфавиту» / «в обратном алфавитном порядке» | name_asc / name_desc | Название без учёта регистра, ё считается е |
| «Сначала недавно добавленные» / «сначала давно добавленные» | created_desc / created_asc | Время создания записи |

Фильтр периода продолжает применяться к началу встречи, времени напоминания или сроку
задачи. Сортировка не меняет фильтр и не скрывает прошлые записи из явно выбранного
периода. В пределах прошлого периода time_asc также означает календарный порядок,
а не абсолютное расстояние от текущего момента. Неизвестные даты/длительности идут
в конце при обоих направлениях; одинаковые значения упорядочены по UUID по возрастанию.
Длительность существует только у встреч с заданным окончанием. Для такого порядка
в строках показаны часы/минуты; неизвестная длительность прямо обозначена.
Приоритета у записей пока нет, поэтому сортировка «по важности» не придумывается.

Можно сказать: «Покажи две самые длинные встречи завтра», «Покажи напоминания за неделю
от поздних к ранним», затем «Теперь по алфавиту». При смене порядка агент повторяет
выборку с прежними фильтрами. Это новая выборка, записи не изменяются.

## Где выполняется работа

- `app/planner/query.py`: необязательный RecordQuery.sort; None сохраняет прежний порядок прямых вызовов.
- `app/storage/postgres/records.py`: явная SQL-сортировка до LIMIT/OFFSET, с владельцем и NULLS LAST.
- `app/mcp_server/schemas.py`: тот же порядок при объединении страниц разных типов.
- `app/mcp_server/tools.py`, `server.py`: sort/limit инструментов, проверка значений и границ.
- `app/agent/presentation.py`: короткие нумерованные строки и ограничение размера сообщения.
- `app/agent/agent.py`: список из результатов read-only инструментов; уточнения и изменение записей
  сохраняют свой сценарий. Итоговый список сохраняется в истории как ответ агента.
- `app/llm/prompts.py`: интерпретация просьбы о порядке и правила чата.
- `app/llm/speech.py`: to_chat_text сохраняет строки; отдельный to_speech_text продолжает готовить текст для TTS.
- `evals/checks.py`, `run.py`: для ответа в чате разрешены переносы и нумерация; строгая проверка TTS сохраняется.

Новых зависимостей, миграций и изменений MAX API нет. Старые Redis-репозитории записей
явно отклоняют sort, поскольку не имеют нужных индексов; рабочая система использует
PostgreSQL. In-memory задачи поддерживают порядок для локальных примеров, сохраняя
прежнее ограничение фильтрации периода по created_at.

## Ограничения и проверка

MCP: период — максимум 100 записей, поиск — максимум 50 (по умолчанию 10).
SQL упорядочивает до ограничения, поэтому запрос «две самые длинные» выбирает их из
всех подходящих записей. В чате максимум 20 строк и 3800 символов, чтобы ответ обычно
помещался в редактируемое сообщение MAX. Длинная выдача заканчивается «Показано: N.
Уточните период или поиск». Меньший limit применяется по просьбе пользователя.
При явно запрошенном top N отдельный footer об ограничении MCP не нужен; если N
не помещается в 20 строк/3800 символов, предупреждение о фактическом сокращении остаётся.
На предельной странице периода из 100 элементов truncated остаётся консервативным
сигналом: дополнительные записи возможны; точное общее количество не вычисляется.

Поиск для переноса с уточнением не заменяется обычной выдачей, а создание продолжает
подтверждаться коротким текстом после успешного инструмента. Нумерация действует в
показанном списке и не заменяет устойчивый ID записи. Значения сортировки, выбранные
LLM из свободной речи, остаются предметом проверки качества модели.

Поведение проверяют tests/test_agent_presentation.py, tests/test_speech.py,
tests/storage_pg/test_repositories.py, tests/mcp_server/ и tests/test_agent_integration.py.
