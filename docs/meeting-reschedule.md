# Перенос встречи и время словами

Теперь также доступны [переименование, изменение времени всех типов и удаление](event-editing.md).

Путь: MAX → AgentBackend → Assistant → MCP `reschedule_meeting` → MeetingService →
PostgreSQL. Меняется существующая запись: ID, владелец, название, описание и время
создания сохраняются. Перед запуском новой версии: `alembic upgrade head`.

## Контракт переноса

Аргументы модели: `meeting_id` (UUID из поиска/истории), `datetime` (новое начало),
`end_time` (новое окончание). Нужен хотя бы один новый момент с UTC/явным смещением.
Владелец и action_id приходят через доверенные заголовки, а не от модели.

- Только начало: сохраняется известная длительность. Неизвестное окончание не появляется.
- Только окончание: начало сохраняется.
- Оба момента: новый интервал; окончание строго позже начала.
- Новая дата без часа: агент использует прежний локальный час и называет время в ответе.
- Несколько подходящих встреч: агент уточняет выбор. Новую встречу для переноса не создаёт.

Ответ: `{"updated": EventDTO}`; только он подтверждает изменение.
Чужая/отсутствующая встреча → `not_found`; неверное время → `validation_error`;
другие аргументы с прежним action_id или конкурентное изменение → `operation_conflict`;
сбой хранилища → `temporary_unavailable`.

Отпечаток включает ID и явно переданные новые моменты. Одно действие не сдвигает
встречу дважды. Повтор возвращает текущее состояние: более поздний перенос не отменяется.
История операций без TTL; очистка пока не реализована. PostgreSQL блокирует строку,
сравнивает прежнее время и фиксирует изменение вместе с действием одной транзакцией.
Миграция 0002 расширяет допустимые типы операций; существующие записи не переписывает.

## Время словами

`app/agent/time_input.py` проверяет наличие времени, а не вычисляет даты.
Перевод в ISO выполняет LLM с reference_time и IANA-зоной пользователя.
Сервер проверяет aware-моменты и порядок границ.

Проверенная лексика: «с часу до пяти», «с одного до пяти», «к двум», «в пять вечера»,
«в половине третьего дня», «полтретьего дня», «без четверти шесть вечера»,
«в четверть шестого вечера», числовое время и относительные интервалы.
Час с частью суток распознаётся и внутри полного сообщения без предлога:
«Завтра встреча, 10 утра», «Напомни завтра 5 вечера позвонить».
Проверка не должна блокировать уже правильно извлечённое моделью время только
из-за отсутствия «в» перед часом. Числа без признака времени («10 задач») этого правила не получают.
Промпт отдельно требует чистые ISO-значения без служебного текста и пропуск отсутствующих
аргументов вместо строки `"null"`; некорректные значения продолжают отклоняться сервером.
Для дневной встречи «с часу до пяти» без указания ночи принята политика 13:00–17:00
в промпте. Явное «ночи», «утра», «дня», «вечера» имеет приоритет.
Если часть суток остаётся неоднозначной, агент должен уточнить её. «Завтра вечером»
не задаёт точного часа. Это ограниченный словарь плюс интерпретация LLM, а не гарантия
понимания любой разговорной фразы. Переходы часов нельзя разрешать догадкой.

## Прототипный Redis-адаптер

Рабочий бот хранит встречи в PostgreSQL. RedisMeetingRepository остаётся совместимым
прототипным адаптером: JSON и owner-индекс начала меняются атомарно, TTL не добавляется.
Операция: `<prefix>:v1:operation:reschedule_meeting:<owner hex>:<operation hex>`.
Область Redis-операции отделена от прежних `create_meeting`; PostgreSQL, как и прежде,
дополнительно запрещает один action_id для разных типов действий одного владельца.

Пояснение скрипта `RESCHEDULE` в `app/storage/redis_meetings.py` по порядку команд:

| Команда | Назначение |
| --- | --- |
| GET KEYS[3] | Проверить сохранённую операцию |
| if saved | Вернуть повтор; Python проверяет fingerprint и читает текущее состояние |
| GET KEYS[1] | Прочитать прежнюю запись |
| if not old | Отсутствующую запись не создавать |
| old ~= ARGV[1] | Отклонить конкурентную перезапись |
| TYPE KEYS[2] | Проверить тип owner-индекса до записи |
| ZSCORE | Проверить прежний элемент индекса до записи |
| SET KEYS[1] | Сохранить новый JSON |
| ZREM | Удалить старое время из индекса |
| ZADD | Добавить новое время, порядок дополнен ID |
| SET KEYS[3] | Сохранить fingerprint и результат без TTL |
| return | Вернуть подтверждённую запись |

Ожидаемые ошибки проверяются до записи: Lua исполняется атомарно, но Redis не
откатывает команды при ошибке скрипта. Ограничения сохранности Redis из основной
документации продолжают действовать.

## Проверка в чате

1. «Завтра встреча с часу до пяти по обсуждению хакатона».
2. «Перенеси обсуждение хакатона на послезавтра в три часа дня».
3. «Какие встречи у меня послезавтра?» — та же запись, 15:00–19:00.

При неоднозначном поиске уточните название/день. Удаление, переименование,
участники и конфликты календаря в этот блок не входят.
