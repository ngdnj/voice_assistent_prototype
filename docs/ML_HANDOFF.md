## Главное правило

**Источник истины — `origin/main`:** `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/C4.md`, `docs/backend-contracts.md`, `README.md` и код.
ML-часть им не противоречит. Если решение из этого файла расходится с `main`, побеждает `main`: исправь этот файл и скажи пользователю.

- **Перед началом любой работы — проверить изменения на GitHub** (просьба пользователя):
  1. `git fetch --all --prune`, затем `git branch -r` — какие ветки появились или пропали;
  2. `git log --oneline HEAD..origin/main` и `git log --oneline HEAD..origin/feature/ml-llm-asr` — что пришло в `main` и в нашу ветку (её мог обновить другой чат);
  3. `git diff --stat HEAD origin/main -- AGENTS.md docs README.md pyproject.toml` — если менялись правила, документы или общие файлы, перечитать их и сверить с этим файлом;
  4. состояние PR — открыт ли, есть ли конфликты, комментарии. `gh` не установлен, поэтому спросить у пользователя или смотреть страницу PR;
  5. если в `main` что-то новое — сказать пользователю до начала работы и при необходимости слить (в отдельной копии ветки).
- **Правим только свою часть** (роль 3): `app/llm`, `app/asr`, `app/tts`, `app/config.py`, `app/metrics.py`, `evals/`, ML-тесты, `docs/ML*.md`.
  Чужой код (`app/agent` — роль 1, `app/planner`, `app/storage`, `app/mcp_server` — роли 1 и 4, `bot`, `api`, `workers`) можно менять **только локально для проверки**: не коммитить, оставлять пометку `ROLE 1` / `ROLE 4` в коде и описание в `docs/ML.md`.
- **Коммит и push — только по явной просьбе пользователя,** без строки `Co-Authored-By`. Коммитить только ML-файлы. Force push и переписывание истории — нельзя.
- Сливать `main` в ветку — в отдельной копии (`git worktree add --detach …`), не трогая рабочую папку: в ней много локальных правок.

## 4. Окружение и нюансы (не наступать снова)

- **ОС:** Windows 11, PowerShell и Git Bash. Python 3.12 через uv. Пакет `tzdata` обязателен.
- **Установка:** `uv sync --extra asr --extra compare --extra demo`. **`uv sync` без extras удаляет torch, GigaAM и пакеты демо.**
  ffmpeg стоит через winget. В новом PowerShell сначала обнови PATH: `$env:Path = [Environment]::GetEnvironmentVariable("Path","User") + ";" + [Environment]::GetEnvironmentVariable("Path","Machine")`.
- **Redis:** `docker compose up -d` (`compose.yaml` роли 1, `redis:7.4.2-alpine`). Docker Desktop может быть выключен.
- **`app/runtime.py` роли 1 не работает на Windows:** `loop.add_signal_handler` даёт `NotImplementedError`. Поэтому локально падают 11 тестов `tests/test_runtime.py`, а `python -m app check` возвращает 1. CI идёт на `ubuntu-latest`, там всё зелёное. Это не наша ошибка, наш код не трогать. Локально проверять так: `pytest --deselect tests/test_runtime.py` или запуск в WSL/Docker.
- **PostgreSQL и `pyproject.toml`:** с PR #9 в `compose.yaml` есть PostgreSQL на порту 5433, настройки `POSTGRES_*` и `MCP_*` описаны в `.env.example`. При слиянии `main` локальный extra `demo` конфликтует с `pyproject.toml`/`uv.lock`. Порядок: копия → `git checkout -- pyproject.toml uv.lock` → `git merge --ff-only origin/main` → снова добавить `demo` → `uv lock` → `uv sync` с extras.
- **Демо:** `uv run --extra asr --extra demo uvicorn tools.demo.web:app --port 8000`. Перезапуск: найти процесс, в командной строке которого есть `uvicorn` и `demo.web`.
  Если менялась схема заглушки, база `data/events.sqlite3` дополняется колонками сама. Удалять её не нужно.
- **Секреты в `.env`** (в git не попадает). Значения не печатать, только проверять, что они есть.
  - `GIGACHAT_SCOPE=GIGACHAT_API_B2B`: с `PERS` ключ получает ошибку 400 «scope from db not fully includes consumed scope».
  - `GIGACHAT_CA_BUNDLE_FILE=certs/russian_trusted_root_ca.pem` — сертификат Минцифры, папка `certs/` в .gitignore.
  - Цены токенов стоят 0 (пакет предоплачен). Есть `CLOUDRU_API_KEY`.
- **Деньги:**
  - пакет GigaChat — ~20 млн токенов Lite, ~20 млн Pro, ~27,6 млн Max; eval ×3 расходует ~0,5 млн;
  - Cloud.ru: осталось ~37 ₽ из 150. Платные прогоны — только с согласия пользователя и с оценкой суммы.
- **Особенности GigaChat:**
  - не принимает `anyOf` в схеме функций;
  - новый клиент на каждый кейс ловит 429 на OAuth, поэтому в eval одна модель на прогон;
  - без кэша промпта отвечает ~8 с, с кэшем ~2 с;
  - иногда виснет на 20+ с, поэтому таймаут с повтором;
  - один вызов функции на сообщение: при нескольких делах второй вызов вклеивается в строку (`…+03:00}} assistant function call…`), `normalize_args` это чистит;
  - ошибается на день на концах полуинтервалов и при прошедших днях перед сегодняшним в календаре.
- **GigaChat очень чувствителен к промпту.** Вставка в длинное правило ломает соседние кейсы: так было, когда правило про конец встречи дописали в правило 5. Новое правило — отдельным коротким пунктом. Всё, что можно посчитать, считай в коде и отдавай модели готовым значением: «через N минут», периоды, срок «до конца недели». То, что модель упорно делает неправильно, проверяй в коде (`arg_checks.py`), а не уговаривай промптом.
- **Примеры в промпте не совпадают с фразами eval**, иначе eval проверяет зубрёжку.
- **Консоль:** `PYTHONIOENCODING=utf-8`. curl из Git Bash портит кириллицу — тело запроса писать в файл и отправлять через `--data-binary @file`.
- **Правки файлов скриптом:** `"\n"` внутри Python-строк в heredoc превращается в настоящий перенос строки. Многострочные замены надёжнее делать инструментом Edit.
