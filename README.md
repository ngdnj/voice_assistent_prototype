# Голосовой ассистент — ML-часть (LLM + ASR)

Ветка `feature/ml-llm-asr`. Здесь агент на GigaChat 3.5 (через Cloud.ru Foundation Models), MCP-сервер с инструментами
задач и встреч, распознавание речи GigaAM, набор eval-кейсов для подбора промпта
и температуры и простое веб-демо.

Postgres, MAX-бот и Mini App делаются в других ветках. Здесь хранилище —
SQLite-заглушка с тем же контрактом MCP-инструментов, чтобы агента можно было
отлаживать до появления настоящей БД.

## Схема

```
голос ─▶ ASR (GigaAM) ─▶ текст ─▶ Agent (LangChain + GigaChat) ─▶ ответ ─▶ TTS (браузер в демо)
                                     │   ▲
                       история в Redis   │ MCP tools (FastMCP)
                                     ▼   │
                         create_event / get_event / get_event_by_query ─▶ хранилище
```

| Модуль | Что делает |
|---|---|
| `src/assistant/llm/prompts.py` | Системный промпт: серверное время в ISO с точностью до секунд, день недели, календарь на 14 дней |
| `src/assistant/llm/agent.py` | Один запрос пользователя → вызовы инструментов → ответ, токены, стоимость, латентность |
| `src/assistant/llm/tools.py` | Превращает MCP-инструменты в LangChain tools и подставляет `user_id` сам — LLM его не видит |
| `src/assistant/llm/history.py` | Контекст диалога в Redis для доспрашивания («Поставь встречу» → «На какое время?» → «В 16») |
| `src/assistant/mcp_server/server.py` | FastMCP-сервер, описания сервера и всех параметров |
| `src/assistant/asr/` | Интерфейс `SpeechRecognizer` и реализация на GigaAM |
| `src/assistant/metrics.py` | Метрики Prometheus: латентность по этапам, токены, стоимость запроса |
| `evals/` | Кейсы из ТЗ и перефразировки, раннер с отчётом |

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). Для голоса нужен ffmpeg в PATH
(`winget install Gyan.FFmpeg`), для истории — Docker.

```bash
uv sync --extra asr              # без --extra asr ставится только текстовая часть, без torch
cp .env.example .env             # вписать CLOUDRU_API_KEY (или GIGACHAT_CREDENTIALS и LLM_PROVIDER=gigachat)
docker compose up -d redis       # или оставить REDIS_URL пустым — история в памяти
```

Текстовый чат в терминале:

```bash
uv run python -m assistant.demo.cli --debug
```

Веб-демо с микрофоном на http://localhost:8000, метрики на `/metrics`:

```bash
uv run --extra asr uvicorn assistant.demo.web:app --port 8000
```

MCP-сервер отдельно (по умолчанию он запускается внутри процесса агента):

```bash
uv run python -m assistant.mcp_server.server     # http://127.0.0.1:8001/mcp, затем MCP_URL в .env
```

## Eval: подбор промпта, модели и температуры

```bash
uv run python -m evals.run                         # все кейсы
uv run python -m evals.run -k today search_        # только кейсы с такими префиксами id
uv run python -m evals.run --repeat 3 --temperature 0.3 --model GigaChat-2-Pro
```

Все кейсы выполняются в один и тот же фиксированный момент: понедельник,
19.10.2026, 12:00 по Москве. Поэтому проверки относительных дат детерминированы.
Каждый кейс проверяет, какой инструмент вызван и с какими аргументами: тип
записи, точное время или дату, диапазон периода, ключевые слова поиска. В выводе
есть доля пройденных кейсов по категориям и p50/p95 латентности и стоимости.
JSON-отчёт сохраняется в `evals/reports/`, по нему удобно сравнивать версии промпта.

### Последний прогон

`ai-sage/GigaChat3.5-432B-A28B-Reasoning`, temperature 0.1, 19.10.2026:

| | |
|---|---|
| Кейсы | 22/22: create 9/9, list 7/7, search 3/3, clarify 2/2, smalltalk 1/1 |
| Латентность агента | p50 4,15 с, p95 10,13 с |
| Стоимость запроса | p50 0,38 ₽, p95 0,49 ₽ (96 ₽ / 1M входных, 289 ₽ / 1M выходных токенов) |

Первый прогон дал 19/22. Модель говорила «создал задачу», не вызывая инструмент, спрашивала
время у задач и отвечала с markdown. Это исправлено правилами 5 и 7 в промпте и проверкой
«ответ пригоден для озвучивания» во всех кейсах.

## Проверки

```bash
uv run ruff check . && uv run ruff format --check . && uv run mypy src evals && uv run pytest
```

Тесты работают без LLM и без сети: используется скриптованная модель и MCP-сервер в памяти.

## Решения, принятые самостоятельно

- **`user_id` не передаётся через LLM.** Он убирается из схемы инструментов и
  подставляется кодом, поэтому промпт-инъекцией нельзя прочитать чужие записи.
- **Календарь в промпте.** Помимо времени и дня недели в промпт передаётся
  таблица дат на две недели вперёд. Модели заметно надёжнее находят «в пятницу» или
  «на следующей неделе» по таблице, чем считают даты сами.
- **Недостающее время проверяется дважды.** Промпт велит спросить время для встречи
  или напоминания. Если модель всё же вызовет инструмент без времени, сервер вернёт
  ошибку, и модель задаст вопрос пользователю.
- **Тип по умолчанию.** «Напомни» — reminder, встреча или созвон — meeting, всё
  остальное — task. Для задачи с датой, но без времени срок — 23:59 этого дня.
- **Время.** Все даты хранятся с часовым поясом, в инструменты передаются в ISO 8601.
  Периоды задаются диапазоном `start_time`/`end_time`.
- **Стоимость** считается из `usage_metadata` по цене за 1000 токенов из конфигурации.
  В Prometheus она записывается гистограммой, чтобы в Grafana получать p50/p95 через
  `histogram_quantile`.
- **Поиск в заглушке** — совпадение по основам слов. В Postgres его заменит
  полнотекстовый индекс по `description` (GIN, `to_tsvector('russian', ...)`).
