# MAX-бот IT Gorky (роль 2)

Бот — точка входа голосового ассистента в мессенджере MAX. Он принимает текст и голосовые
сообщения, передаёт их агенту, показывает пользователю ход обработки и ответ, а в нужное
время присылает напоминания.

Бизнес-логики в боте нет: задачи, встречи и напоминания создаёт агент через MCP. Бот отвечает
за общение с MAX, порядок обработки, Redis и доставку уведомлений.

## Что умеет бот

- **Приветствие.** При первом входе и по `/start` бот здоровается и предлагает написать текст
  или записать голосовое.
- **Текст.** Сообщение уходит агенту, пользователь сразу видит «Принял запрос, обрабатываю…».
  Ответ агента заменяет это сообщение.
- **Голос.** Бот скачивает запись с серверов MAX, распознаёт её (GigaAM, роль 3) и передаёт
  текст агенту так же, как обычное сообщение.
- **Один запрос за раз.** Пока запрос обрабатывается, на любое новое сообщение бот отвечает
  «Сейчас обрабатывается ваш предыдущий запрос. Повторите попытку чуть позже.».
- **Защита от мусора.** Сообщение только из смайликов или знаков получает «Введите корректный
  запрос.», стикер или картинка — подсказку, что бот понимает текст и голос.
- **Кнопки подтверждения.** Готовы кнопки «Да, все верно» и «Нет» («Нет» → «Повторите запрос.»).
  Агент пока отвечает без кнопок.
- **Напоминания.** В назначенное время пользователь получает «🔔 Напоминание: <название>»
  и описание с новой строки.
- **Повторы MAX.** Одно и то же событие от MAX обрабатывается один раз.

## Как это устроено

```text
MAX ──webhook──▶ webhook.py ──▶ updates.py (разбор) ──▶ service.py (BotService)
                                                         │  дедупликация и блокировка — gate.py (Redis)
                                                         │  статус «Принял запрос…» — client.py
                                                         ▼
                                   фоновая обработка: голос ─▶ ASR (роль 3) ─▶ текст
                                                       текст ─▶ AgentBackend (роль 1) ─▶ MCP / PostgreSQL
                                                         ▼
                                   ответ заменяет статус ─▶ пользователь

PostgreSQL (напоминания) ─▶ reminders.py ─▶ Redis Stream ─▶ delivery.py ─▶ MAX ─▶ пользователь
```

| Модуль | Ответственность |
| --- | --- |
| `__main__.py` | запуск: `webhook`, `polling`, подписки, `doctor`; сборка всех частей и остановка по Ctrl+C |
| `settings.py` | настройки из переменных окружения и их проверка |
| `client.py` | клиент MAX Bot API: отправка, правка и удаление сообщений, загрузка аудио, подписки |
| `updates.py` | разбор событий MAX в типы `BotStarted`, `MessageCreated`, `CallbackPressed`, `Ignored` |
| `service.py` | сценарий бота: приветствие, статус, блокировка, голос → ASR → агент, ответ |
| `gate.py` | Redis: блокировка «один запрос на пользователя» и дедупликация событий |
| `webhook.py` | HTTP-приём событий MAX с проверкой секрета |
| `polling.py` | long polling — запасной режим без публичного адреса |
| `delivery.py` | доставка уведомлений из Redis Stream пользователю |
| `reminders.py` | **временный** планировщик напоминаний, до появления dispatcher роли 1 |
| `doctor.py` | пошаговая проверка цепочки webhook |
| `messages.py` | все тексты для пользователя |
| `metrics.py` | метрики Prometheus |

## Что нужно для запуска

- Python 3.12 и [uv](https://docs.astral.sh/uv/);
- Docker Desktop — для Redis и PostgreSQL;
- [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) — HTTPS-туннель для webhook;
- ffmpeg — для распознавания голоса;
- токен бота MAX, доступ к GigaChat.

Первая установка зависимостей (с моделью распознавания GigaAM):

```powershell
uv sync --extra asr
```

### Настройки `.env`

Скопируйте `.env.example` в `.env` в корне проекта и заполните. Для бота важны:

| Переменная | Что указать |
| --- | --- |
| `MAX_BOT_TOKEN` | токен бота из кабинета MAX |
| `MAX_WEBHOOK_SECRET` | любая строка 5–256 символов из `A–Z a–z 0–9 _ -`; без неё webhook не запустится |
| `MAX_CA_BUNDLE_FILE` | `russian_trusted_root_ca.pem` — сертификат Минцифры в корне проекта (в git не попадает) |
| `MAX_AUDIO_HOSTS` | можно не задавать: по умолчанию `max.ru,oneme.ru` — откуда разрешено скачивать голосовые |
| `MCP_URL`, `MCP_SERVICE_TOKEN` | адрес MCP-сервера и общий токен не короче 32 символов |
| `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE`, `GIGACHAT_CA_BUNDLE_FILE` | доступ к GigaChat; сертификат тот же `russian_trusted_root_ca.pem` |
| `REDIS_*`, `POSTGRES_*` | можно оставить как в `.env.example` для локального Docker |

Пути в `.env` должны вести к файлам на **вашем** компьютере. Если `.env` взят у коллеги,
проверьте пути к сертификатам. Полный список настроек бота — в `INTEGRATION.md`, раздел 7.

## Запуск: четыре окна PowerShell

В каждом окне сначала перейдите в корень проекта.

**Окно 1 — Redis, PostgreSQL и таблицы** (Docker Desktop должен быть запущен):

```powershell
docker compose up -d --wait redis postgres
uv run --locked --env-file .env alembic upgrade head
```

**Окно 2 — MCP-сервер:**

```powershell
uv run --locked --env-file .env python -m app.mcp_server
```

**Окно 3 — бот:**

```powershell
uv run --locked --env-file .env python -m app.bot webhook
```

В логе должны появиться `bot_webhook_started`, `delivery_started`, `reminders_started`
и, если включён голос, `asr_warm_up_finished`.

| Флаг | Что делает |
| --- | --- |
| `--text-only` | без распознавания голоса (не загружает GigaAM) |
| `--no-reminders` | без доставки уведомлений и планировщика напоминаний |
| `--port 8765` | другой порт, если 8080 занят |

**Окно 4 — туннель:**

```powershell
cloudflared tunnel --url http://127.0.0.1:8080
```

Скопируйте адрес вида `https://<слова>.trycloudflare.com`. Пишите `127.0.0.1`, а не `localhost`.

**Снова окно 1 — подписка и проверка:**

```powershell
uv run --locked --env-file .env python -m app.bot subscribe --url https://<адрес-туннеля>/max/webhook
uv run --locked --env-file .env python -m app.bot doctor
```

Подписку нужно обновлять при каждом новом адресе туннеля и после смены `MAX_WEBHOOK_SECRET`.
`doctor` по шагам проверяет секрет, Redis, токен, подписку, локальный сервер, туннель
и пробное событие и подсказывает, где сломалось.

### Остальные команды

```powershell
uv run --locked --env-file .env python -m app.bot subscriptions                 # текущие подписки
uv run --locked --env-file .env python -m app.bot unsubscribe --url <адрес>     # удалить подписку
uv run --locked --env-file .env python -m app.bot polling --text-only           # long polling, без туннеля
```

Long polling работает только без активной подписки, а нативные голосовые MAX в этом режиме
присылает пустыми. Поэтому основной режим — webhook.

## Как проверить вручную

1. Нажмите «Начать» в чате с ботом — придёт приветствие.
2. Напишите «Создай задачу подготовить отчёт на завтра» — появится статус, потом ответ агента.
3. Пока идёт обработка, отправьте ещё сообщение — бот ответит, что занят.
4. Отправьте «😀😀» — «Введите корректный запрос.».
5. Запишите голосовое — бот распознает его и ответит так же, как на текст.
6. Напишите «Напомни через 2 минуты выпить воды» — через две минуты придёт напоминание,
   в логе появится `reminder_published`.

## Напоминания

```text
PostgreSQL events (reminder, время наступило)
  ─▶ reminders.py, раз в 5 с ─▶ поток it-gorky:v1:notifications:max
  ─▶ delivery.py, группа max-delivery-v1 ─▶ POST /messages?user_id=<owner_id> ─▶ отчёт и ACK
```

- **Планировщик (временный).** Раз в 5 секунд читает из PostgreSQL наступившие напоминания,
  только чтение. Что уже отправлено, помнит Redis, поэтому после перезапуска повторов нет.
  Перенесённое напоминание срабатывает в новое время, удалённое не срабатывает. Пропущенные
  больше часа назад, пока бот был выключен, не отправляются.
- **Доставка.** Работает строго по контракту `docs/notification-stream.md`: не больше трёх
  попыток, зависшие записи забираются заново, неудачные уходят в поток
  `it-gorky:v1:notifications:dead`.
- **Получатель** — `owner_id`; у пользователей бота это их MAX `user_id`.
- Когда dispatcher роли 1 начнёт сам публиковать напоминания, `reminders.py` удаляется,
  а доставка остаётся без изменений.

## Тесты

```powershell
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest -q tests/bot
```

Тесты с настоящими Redis и PostgreSQL включаются отдельно и работают только с тестовыми
базами: свои ключи они создают с префиксом `it-gorky:test:<uuid>` и удаляют после себя.

```powershell
$env:RUN_REDIS_INTEGRATION="1"; $env:RUN_PG_INTEGRATION="1"; $env:POSTGRES_TEST_DB="it_gorky_test"
uv run --locked --env-file .env pytest -q tests/bot
```

CI на GitHub запускает все проверки сразу, с Redis и PostgreSQL. На Windows могут падать
тесты `tests/test_runtime.py` роли 1 — это не связано с ботом, в CI они проходят.

## Частые проблемы

| Что видно | Причина и что делать |
| --- | --- |
| `{"event": "bot_start_or_runtime_failed"}` | ошибка в `.env`: нет `MAX_WEBHOOK_SECRET`, неверный путь к сертификату, не заданы `MCP_*` или `GIGACHAT_*`, занят порт 8080 |
| `{"event": "redis_unavailable"}` | не запущены контейнеры: `docker compose up -d --wait redis postgres` |
| `{"event": "polling_failed", "error_code": "tls_certificate"}` | не подключён сертификат Минцифры: `MAX_CA_BUNDLE_FILE` |
| «Не получилось обработать запрос» | не запущен MCP-сервер, нет таблиц (`alembic upgrade head`) или GigaChat отказал в доступе |
| бот молчит | неверная или старая подписка: снова `subscribe` с текущим адресом туннеля, затем `doctor` |
| `subscribe` → `http_504` | туннель ещё не поднялся или мешает VPN; подождите и повторите |
| cloudflared: `dial tcp [::1]:8080` | в адресе туннеля `localhost` — замените на `127.0.0.1` |
| «Не удалось прочитать запись» | `audio_source_rejected` в логе: добавьте домен в `MAX_AUDIO_HOSTS` |
| «Не удалось распознать голосовое» | нет ffmpeg или GigaAM: установите ffmpeg и `uv sync --extra asr` |
| `reminders_postgres_unavailable` | PostgreSQL не запущен или неверные `POSTGRES_*` |

## Ограничения

- Обработка запросов идёт в процессе бота и не сохраняется: если процесс упадёт, запрос
  потеряется, а блокировка пользователя снимется сама через 3 минуты. Надёжная очередь
  заданий — задача роли 1.
- Напоминание приходит с задержкой до 5–6 секунд. Сбой ровно между отправкой и подтверждением
  может дать дубль — это ограничение контракта уведомлений.
- Часовой пояс пока один на всех (`MAX_DEFAULT_TIMEZONE`), профиля пользователя нет.
- Webhook-сервер бота — стенд для разработки; в рабочей системе маршрут подключает роль 1.
